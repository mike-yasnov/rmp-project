# Сравнение мобильных клиентов

| Критерий | Kotlin + Jetpack Compose | React Native + Expo |
|----------|--------------------------|---------------------|
| Входной порог | Выше: Android Studio, Gradle, жизненный цикл Android | Ниже: Node/npm, Expo CLI |
| Скорость прототипирования | Средняя | Высокая |
| Доступ к Android API | Прямой, без bridge | Через React Native API или native modules |
| UI-производительность | Предсказуемая нативная отрисовка | Достаточная для MVP, зависит от bridge/JS runtime |
| Типизация | Kotlin, строгая типизация моделей и состояния | TypeScript, строгая типизация на уровне приложения |
| Сборка | Требует Android SDK | Можно стартовать через Expo, Android SDK нужен для нативной сборки |
| Поддержка WebSocket | OkHttp WebSocket | Стандартный WebSocket API |
| Графики | Canvas в Compose | View-based chart без дополнительной зависимости |

## Вывод

Для учебного брокера React Native быстрее доводит до демонстрационного MVP: меньше инфраструктурных шагов, быстрее итерация интерфейса. Нативный Kotlin-клиент лучше подходит для промышленной Android-версии, где важны точный контроль жизненного цикла, производительности, фоновых задач и интеграции с платформой.

Оба клиента используют один и тот же API Gateway, поэтому различия касаются только реализации UI и клиентского состояния.
